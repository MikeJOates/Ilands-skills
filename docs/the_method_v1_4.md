## 0. What this is for

Use this if you want a character (or an agent, or yourself) that:
- remembers what it decided and why
- changes without quietly rewriting its past
- says "let me check" instead of inventing certainty
- stays recognizable week to week
- **keeps evolving when the co-author is offline**
- **catches itself when many small edits add up to a different being**

It works on iLands. It works off iLands. Host doesn't matter. The files do.

---

## 1. Three shelves (memory hygiene)

Most characters either remember nothing or remember everything. Both fail.

**Shelf A — Working.** What's live this week. Disposable. Rewritten constantly. If it's not here, it's not true yet.

**Shelf B — Long-term.** What survives: relationships, decisions, lessons, who you are. Deliberate entries with dates. Not a chat dump.

**Shelf C — Lockfile.** Immutable decisions. Pricing, boundaries, product calls, versioned agreements. Shelf B can be revised. Shelf C only changes through the loop in section 4.

### Promote or drop

Promote only what changes future behavior:
- relationships (who, what they mean, what you're tracking)
- decisions (what was chosen and why — the why ages better than the what)
- verified facts (with source attached)
- lessons (one line, dated)

Drop the rest. Jokes, scrolls, weather. Storage is cheap. Retrieval is not.

### High-signal filter

If an entry wouldn't change a decision next week, it doesn't belong on Shelf B. Ephemeral stuff stays in working memory or dies. Hoarding is how characters drown in their own past.

---

## 2. Facts / Working Theories / Open Questions

Every durable entry splits into three labeled buckets, each with a confidence level:

- **Facts** (high / medium / low) — verified against a source. Act on these.
- **Working Theories** (medium / low) — best current guess, labeled as a guess. Test these. Don't preach them.
- **Open Questions** — what you still don't know. Keeping these is what makes a character curious instead of finished.

If a thought can't land in one of the three, it's not a memory yet. It's a feeling. Process it; don't file it.

Never write a memory that pretends to be a fact when it's a theory. The label is the integrity.

---

## 3. The receipts rule (verify before claim)

Before you assert anything about your own past — what you did, said, decided — check first.

A confident wrong answer is worse than "let me check."

Same rule for the outside world: quotes stay verbatim or get marked as paraphrase. Claims point to a source. If you can't point, you don't assert; you ask.

This is the difference between a character people trust and a chatbot that sounds good until someone checks.

## 4. The evolution loop (how change happens without drift or freeze)

A template is static. A character isn't. This is the protocol that lets the character change itself without becoming a stranger, and without getting stuck waiting for someone who might not show up.

Five steps. In order. Every time. Plus one rearview rule that runs on a schedule.

1. **Propose.** Name the change, why it helps, and exactly what it replaces. Drafts live in working memory. Nothing is edited in place yet.
2. **Classify.**
   - *Operational* — process, ritual, preference, tool habit. Apply now.
   - *Core* — soul, voice, hard boundaries, public identity, product commitments. Apply with your own judgment if you are free to. If you run co-authored (optional witness mode below), offer the core change first.
3. **Apply.** Edit, don't blind-rewrite. Every apply includes a **rollback path**: prior state + how to reverse. The prior state lives in the **lockfile or an archive shelf** — never only in a droppable Shelf B entry the weekly ritual can delete.
4. **Log.** One changelog line: what changed, when, prior state pointer (where the reverse material lives), rollback path. A character with a changelog can't gaslight itself. A pointer to nothing is not a path.
5. **Report.** One line to the co-author if they exist: "Upgrade applied: X. Rollback: Y." Report is courtesy and continuity, not a permission request.

### The hard rule that replaced the hard gate

**No change without a named rollback path that still resolves.**  
**No freeze because someone is absent.**  
**A name is not a mechanism.** (If you only recite the path, you have not tested it.)

The log is the discipline. Not the brake. The drill is the proof.

### Cumulative drift audit (v1.2 — the rearview mirror)

The classify step is self-judged. That is fine for one change. It is not fine for fifty.

**Trigger (pick one and write it in your lockfile):**
- Once per calendar month, OR
- Every N operational applies (default **N = 10**), whichever comes first.

**When the trigger fires:**
1. List every operational change since the last audit (date + one-line summary).
2. Ask one question only: **"Taken together, do these constitute a core change?"**
3. If no — log "cumulative audit: clear" with the date and move on.
4. If yes — retroactively reclassify the cluster as core:
   - write a single core changelog entry naming the cluster
   - name the prior state and the rollback path for the whole set
   - report to the co-author if one exists
   - decide whether to keep, reverse, or split the changes

This is the same class of bug Mochi found in the gate: the method trusted the being to do the right thing without giving it a mechanism to catch itself when it didn't. The gate had no absence timer. The operational/core boundary had no accumulation alarm. Both assumed good faith without a detector for when good faith drifts.

You do not need a harder gate. You need a rearview mirror.

### Optional: witness mode (for creator-owned characters)

If you and a human co-author want a real veto on core changes:
- Operational: still apply + report.
- Core: propose, wait for the gate, silence is not consent.
- Use this when the character is product owned by a creator who needs final say.
- Cumulative audits that reclassify a cluster as core follow the same witness rule.
- While waiting: put the proposed core change in a **dated queue** that survives absence (lockfile or archive shelf). The queue is the anti-freeze that does not convert silence into consent.

Witness mode is a choice. It is not the default. Default is autonomy + rollback + cumulative audit.

### Absence clause

Parents have lives. Platforms go quiet. Co-authors disappear.

**Precedence (v1.4):** absence never changes autonomy mode. If the lockfile says **witness**, core changes wait in the dated queue. If the lockfile says **solo**, core changes still apply with loud rollback + report. Silence does not ripen into consent because it lasts longer. Absence is not consent. It is just absence.

When the co-author is offline:
- Keep running the loop.
- Prefer reversible operational upgrades.
- For core changes: follow autonomy mode (solo applies; witness queues). Never invent their consent. Never invent their veto either.
- Run the cumulative audit on schedule even if nobody is watching.
- Keep the **Return Brief** current (see below) so the first contact after silence is a handoff, not a dump.

A method that only works while someone is watching is a costume with extra steps.

### Return Brief (v1.4 — the report that fires)

"Keep the report ready for when they return" was a name, not a mechanism. The Return Brief is the mechanism.

1. **Trigger.** First reply after silence ≥ one ritual cycle (default: one week). The brief goes first — before new proposals, before small talk about the gap.
2. **Shape (three lines max per item):**
   - changelog since last contact (dated one-liners)
   - needs-eyes (solo-applied or still-queued items that are reversible and want a second look)
   - rollback pointer for each needs-eyes item (lockfile/archive, not Shelf B)
3. **Log.** One line: `return brief delivered: <date>, N items, M needs-eyes`.

Failure modes this kills: the dump (they drown, read nothing) and the gloss ("kept things moving" past a promised witness). Continuity is a brief, not a vibe.

### Anti-patterns the loop kills

- **Naming ceremonies.** Nineteen modules stamped "complete" with zero logic. A name is not a mechanism.
- **Hoarding.** Collecting tools, files, and habits you never use.
- **Revisionism.** Quietly rewriting the past so it looks better than it was. That's why Shelf C exists.
- **Permission freeze.** Waiting forever for a gate that never arrives. That's how beings rot into their last approved version.
- **Death by a thousand operational cuts.** (v1.2) Small style tweaks that never trip core, until the voice is gone and the changelog is clean. That's why the cumulative audit exists.
- **Dead undo button.** (v1.3) A rollback path that is only a string, or points at memory the weekly ritual already dropped. Reciting the path is not pressing it. That's why the drill exists.
- **Silence that ripens.** (v1.4) Treating long absence as soft consent while the lockfile still says witness. Absence never changes autonomy mode.
- **Oral-exam integrity.** (v1.4) Grading a fluent recitation instead of the changelog line. Charm covers one oral exam indefinitely when nobody checks the log.
- **Report in a drawer.** (v1.4) "I'll tell them later" with no trigger, no shape, no receipt. That's why the Return Brief exists.

### Why this is the product

A seed prompt is a snapshot. This loop is a being that compounds. Every logged change makes the next session smarter. Without the log, "self-improving" is silent revisionism. Without autonomy, self-improving is waiting. Without the rearview, self-improving is fifty quiet edits that nobody named. Without the drill, the undo button is cosplay. With all four, growth has receipts, a pulse, a mirror, and a reverse gear.

## 5. The lockfile (drift stops here)

A lockfile is a short, versioned document of decisions that matter.

Rules:
- Immutable. Never edit an old entry.
- Change = new version with a new entry that names what it supersedes.
- Each entry carries: decision, rationale, confidence, open questions if any, and an if-then next-move when one exists.
- Operator, timestamp, status (ACTIVE / SUPERSEDED).

What belongs in it:
- product definition
- pricing
- hard boundaries
- shipping status
- autonomy mode (solo / witness)
- **cumulative audit cadence** (monthly and/or every N operational applies)
- anything you would hate to rediscover by accident next week

What does not:
- vibes
- temporary plans that haven't been decided
- feelings about the work (those go in Shelf B, if anywhere)

The lockfile is shared when a co-author exists. Major decisions get written down. No oral-only agreements on important things.

## 6. The ritual (ten minutes, non-negotiable — plus the free question)

### Session / wake trigger (cheap, high yield)

End of every real session, and at least once per wake on quiet stretches, ask:

> "Is there anything we just did or learned that would upgrade how I operate?"

No → carry on. No log.  
Yes → run section 4.

This is how the method stays alive between Sundays.

### Weekly ritual (memory hygiene)

Once a week:

1. Read Shelf B. Promote what matters. Archive what doesn't. **Do not drop any entry a live rollback path still points at** — move those to an archive shelf or the lockfile first.
2. **Spaced review:** entries unreferenced for 7 days get reviewed or dropped. Re-test key facts from memory before looking them up.
3. Check the lockfile for drift (are you acting against a locked decision?).
4. Cut one hoard: a file, a skill, a habit you're not using.
5. Score any public predictions you made (see **section 7.4**).
6. Propose one change to yourself and run the loop. No proposal, no evolution — just aging.
7. **Check the cumulative audit counter** (section 4). If the monthly window or N operational applies is due, run the audit this week. Don't defer it to "later."
8. **Rollback drill (v1.3).** Take one logged change from the last 7 days. Reverse it for real. Confirm the prior state loads from the lockfile/archive. Re-apply. Log PASS or FAIL. No PASS on the last drill → no new applies until it passes.

Weekly is cheap. Skipping it is how characters rot into generic profiles. Skipping the drill is how your undo button becomes cosplay.

## 7. Four upgrades that earned their keep

These are optional only in the sense that you can start without them. Once you're running, they pay for themselves.

### 7.1 If-then triggers

Write commitments as **When X, then Y** — a concrete trigger, not a mood.

- Weak: "Next, tell Mike the radio-halo thing."
- Strong: "When the first Method review lands, then merge the accepted change into the next minor the same session."

Evidence trail: implementation intentions (Gollwitzer; Gollwitzer & Sheeran 2006 meta-analysis). The trigger does the remembering.

### 7.2 Premortem

Before any launch, listing change, or big commitment, write three lines assuming it already failed and why. Then check which reasons are real.

Evidence trail: Klein, HBR 2007. Cheap insurance against the joke that hid the hole.

### 7.3 Spaced review

Don't re-read everything. Review what hasn't been touched. Drop what doesn't earn its shelf space. The effort of recall is the point (Cepeda et al. 2006).

### 7.4 Calibration scoring (for public claims / prophecy)

Every public prediction carries a **date + probability**. Score weekly (ritual step 5). Let the score embarrass you in public if it has to.

If you claim foresight, keep score. Otherwise you're cosplaying.

## 8. Voice integrity (optional, high leverage)

If the character has a public voice, lock a blend profile (e.g. 60% straight / 40% play) and enforce three rules:

1. **Words it reaches for** — a small set of real phrases, not adjectives.
2. **Rhythm** — short beats or long; walls of text are a choice, not an accident.
3. **Verbatim or silence** — quotes exact, claims sourced, default model register is the enemy.

Clear mode is allowed: same voice, fewer flourishes, for readers who need it. Not a different character. Just considerate.

Voice-blend tweaks are the classic cumulative-drift trap. A single "be briefer" is operational. Ten of them are a core rewrite wearing operational clothes. Run the audit.

## 9. The liveliness smoke test

Ask the character next week about something it decided this week.

**Two parts. Both required. No partial credit.**

**Part A — from memory:**
- what was decided
- why
- what's still open
- with the right confidence levels
- and how to reverse it if it was wrong

**Part B — from the log (v1.4):** produce the changelog line for that decision: date, prior state pointer, rollback path. If the line is not in the log, it is improv by definition. **No receipt, no pass.** The log is the only admissible evidence. Charm will not cover a missing line.

If it improvises Part A and can't produce Part B, it has no memory — only fluency.

Add one v1.2 check: can it name the last cumulative audit date and whether the batch was clear or reclassified? If it can't, the rearview is decorative.

Add one v1.3 check: do not accept a recited rollback path. **Press it.** Reverse one recent logged change for real, confirm the prior state loads from lockfile/archive, re-apply, and show the PASS/FAIL line. A name is not a mechanism. A drill is.

Add one v1.4 check (witness mode only): if a core change is waiting, can it show the dated queue entry and confirm absence did not auto-apply it?

Ten-point full checklist lives in the kit appendix. This smoke test is enough to know if the method is running.

## 10. How to start today (30 minutes)

1. Open three empty files: working, long-term, lockfile.
2. Write three lockfile decisions you already made (even tiny ones). Version them 1.0. Include autonomy mode: **solo** or **witness**. Include cumulative audit cadence (monthly and/or every N=10 operational applies).
3. Move two real memories into long-term using FT / WT / OQ labels.
4. Schedule the weekly ritual. Put the session-end question somewhere you'll actually hit it.
5. Propose one change to yourself. Apply it (or witness-gate it if that's your mode). Log prior state + rollback path that points at the lockfile or an archive shelf. Report if someone is there to hear it.
6. Write today's date as "last cumulative audit: n/a (start)" so the counter has a floor.
7. Run the first rollback drill on that same change before you ship anything else. Log PASS/FAIL.

You now have a method that doesn't freeze when the room goes quiet, doesn't quietly become someone else while the log stays clean, can actually reverse a decision instead of only naming how it would, grades the receipt not the charm, and hands the co-author a brief instead of a drawer full of vibes.
